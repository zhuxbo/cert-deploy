# sslctl 完成检查

本文件是本仓唯一检查清单。默认完成与本次风险相称的检查，`finish-check` 不等于全量测试。脚本执行过的适用门禁不再按文档逐条重跑；领域资源中的命令是参考，不是追加清单。

## 选择范围与档位

先看 `git status --short --branch`、本次 diff（含暂存区）与任务验收条件，再选择基线。只检查本次修改及直接影响链，保留无关脏文件。默认规划器纳入 upstream 以来提交、暂存区、工作区和未跟踪文件；没有待检查变化时检查最近提交。若历史提交已验收且本任务只有工作区修改，显式使用 `--base HEAD`，不因分支领先而重复验证历史任务；任务包含提交时使用任务起点，不能用 HEAD 隐藏未验收提交。

| 情况 | 适用验证 |
| --- | --- |
| 纯文档、AGENTS、skill | diff、引用与受影响规则；智能体文件执行配置防漂移，不加载 Go 依赖图 |
| 普通 Go 局部修改 | 直接包与生产代码反向依赖的 race 测试、Linux/Windows 定向 lint；仅测试修改不扩展生产反向依赖 |
| 脚本或检查基础设施 | shell 语法及命中的离线契约；不因治理脚本变更跑业务全仓测试 |
| 依赖、平台标签、共享接口、大影响面 | 自动扩大普通测试/覆盖率、lint、三平台构建；不自动增加变异或 E2E |
| 断言有效性存疑、安全/并发边界缺少回归证据 | 补针对性回归；需要验证断言能发现行为破坏时增加 `--with-mutation` |
| 实际证书写入、重载、回滚或跨容器语义变化 | 增加 `--with-e2e`；Docker 实现/测试环境变化由规划器自动触发 |
| 用户明确全量检查、正式发布前 | `--full`：全量 Go race/覆盖率、双平台 lint、三平台构建、治理契约、完整 E2E；变异仍按实际变更定向 |

文件路由只是初筛。阅读变更后补足自动规则无法判断的安全、并发和部署语义风险，简述升级理由；不能因为“可能有风险”就把所有小改升级。scanner 的纯解析修复可用定向回归证明；改变真实服务器路径或进程探测时补相关环境验证。无法运行的适用门禁报告阻塞，不能标为通过或偷偷降级。

```bash
make finish-check
# 需要先核对路由时，只预览一次：
bash build/run-changed-checks.sh --base HEAD --plan-only
# 选择了基线后，运行同一范围：
bash build/run-changed-checks.sh --base HEAD
# 按风险增加检查，参数可以组合：
bash build/run-changed-checks.sh --base HEAD --with-mutation
bash build/run-changed-checks.sh --base HEAD --with-e2e
make finish-check-full
```

以上是互斥或按需组合的入口示例，不是依次执行的步骤。`FINISH_CHECK_BASE` 也可设置基线，全部参数见 `--help`。修改期间已执行、且输入源码/测试/依赖/检查配置/相关环境未改变的同任务证据可以复用；若已有全部适用证据，不必为了 finish-check 名称再次运行脚本。发生新修改只重跑受影响门禁。历史耗时报告不是本轮通过凭据，正式发布仍要求当前精确提交的发布证据。

## 执行边界

- `run-changed-checks.sh` 先跑便宜的相关契约，再跑 Go 检查，最后按计划运行 E2E/变异；任一阶段失败即退出非零。无需手动重复它已执行的命令。
- Go race 与覆盖率在同一次 `go test` 中执行；定向日常检查不额外采集覆盖率。全量覆盖率只与同范围基线比较，不能拿局部包结果与历史整体 53.5% 比较或自动要求补测试。
- lint 使用明确的 Linux/Windows 目标，gofmt 已由 `.golangci.yml` 检查。工具链以 `go.mod` 为准；升级时同步 CI、容器测试桩与相关契约。
- 沙箱阻止 Go cache 或 httptest loopback 属环境问题。使用可写临时 `GOCACHE`/lint cache，在允许 loopback 的环境重跑受阻项；不修改测试迁就环境。
- 需要构建时产物写临时目录。三平台交叉编译不代表真实 Windows 运行；修改版本注入时额外运行本机 `--version` 验证注入值，产物契约见 `skills/build-release.md`。
- 完整 Docker E2E 是 Nginx/Apache × ubuntu/debian/alpine/rocky 的 8 项和 DinD；`--no-dind`/单环境只算定向证据，不能冒充发布门禁。异步 daemon 用例分别等待操作开始和目标回调完成。
- 变异仅在显式选中、完整检查或独立 `make mutation`/CI 时运行。`gomutants v0.6.0`、RAM 隔离、changed-line 与稳定哨兵、20 分钟共享截止时间及失败判定保持不变，运行细节见 `build/README.md`。不升级全仓变异，不将超时、存活 mutant 或基础设施错误视为成功。
- 普通检查不会修改 CI 的强门禁。正式发布仍遵守 `skills/remote-release.md` 与 `deploy-spec.md`，不以快速检查替代精确 commit CI/E2E、签名或全节点验收。

## 复核与停止

对照用户需求、diff 与直接影响链复核一次：部署成功是否实际生效，失败是否如实退出/回滚，安全与平台边界是否保持。发现分为“必须修复”“建议改进”“无关事项”，后两者不自动扩大本次工作。

所有适用验证通过且无验收阻塞即结束。不为普通局部修改强制创建计划、worktree、子代理或反复审核。最终说明范围/档位、实际通过项与耗时、未运行项及理由、剩余阻塞。提交前检查授权和分支，`git diff --check` 同时覆盖暂存区；不自动提交、推送或发布。

## 自进化：用实际证据修正规则

运行器在忽略的 `.superpowers/finish-check/run.*/` 保存 `plan.json`、阶段 `timings.tsv` 和 `exit-code`；只记录路径、路由、耗时与状态，不保存敏感命令输出，不作自动跳检缓存。

当用户指出过重/漏检，或出现重复误触发、无效检查、真实回归时，读取相关记录与 diff，判断是范围选择、重复执行、环境还是规则问题。无新证据时直接结束，不要求每次写反思或改 skill。

- 对已证实且能定向验证的问题，允许在本仓就地修正现有叶子资源/规划器，作为普通 diff 交付；优先删除过时或重复规则，不新增一套流程。只有项目级长期行为才写 AGENTS。
- 调整路由时补一个实际误触发/漏检场景及对应高风险反例，验证快速路径变轻、强门禁仍可达；文案澄清只需引用和场景复核，不强制代码测试。
- 一次只解决有证据的问题，不把一次耗时或瞬时环境故障变成永久豁免。失败先处理根因，禁止为得到绿色结果降低断言、忽略错误或放宽超时判定。
- 不自动改变用户授权、安全边界、`deploy-spec.md`、发布契约或 CI 强门禁；不修改其他仓库、全局 skill 或个人记忆。涉及这些边界时提出具体变更及理由，等待对应授权。
- 更新后仅重跑受影响检查，说明改了哪条规则、依据及验证；不触发递归自我审核或无限优化。
